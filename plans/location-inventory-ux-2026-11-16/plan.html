Counting and coverage

Reuse Client::notClosed(), market authorization and CityNormalizer city keys. Add lifecycle_state to the endpoint’s selected fields: it is currently absent although isActiveProfile() depends on it. Active follows that existing canonical method. Unlockable requires published status, a positive WordPress post ID and lifecycle expired, matching the public archive unlockable bucket. Archived, removed, private and draft profiles cannot enter Unlockable. Available is the sum of these disjoint buckets. This is CRM cached inventory, not proof of a successful visitor purchase or current advertiser availability.

Keep all cached-client totals independent of availability. Locations with cached profiles and zero Available remain visible and sort first. Cities with no cached clients are outside this first release; do not imply a complete WordPress taxonomy census. No new WordPress request or migration is necessary for this feature. Any unrelated pending migration discovered during deployment is outside this release and must not be run incidentally.

Interaction decisions

Default sort is Available, fewest first, with a city-name tie-break. Search is case-insensitive and trimmed. Count basis supports Available, Active, Unlockable and All clients. Minimum and maximum thresholds are inclusive nonnegative integers; invalid or reversed thresholds show an inline prompt and suppress export. Low inventory applies maximum 5 and ascending count order; staff can edit the threshold. No active profiles applies Active = 0; Unlockable only applies Active = 0 and Unlockable > 0. Off-map and performance filters remain independent and resettable.

The table shows current inventory separately from engagement during the selected 7/30/90-day period. Metadata disclosure exposes verified counts, map state, views, profile-unique visits, contact rate, channel mix and performance explanations. Unavailable stays “Unavailable”; a numeric zero remains zero. Null analytics/index values sort last in both ascending and descending order, and numeric zero is a valid score. Apply this to the table, map tooltips and CitySpotlight metadata. Retain the existing methodology for the index rather than representing Weak as low inventory. Every numeric count and city name is sortable, with accessible sort state and explicit buttons.

Search/filter/sort changes reset pagination. Export includes every filtered row in current sort order, across pages, with the selected period, inventory definitions and availability-preserving engagement values. Escape CSV correctly and neutralize spreadsheet formula cells. Selection follows the filtered array; clear a selected city that no longer matches. A changed market must never display the previous market’s placeholder counts, selection or export. Loading, error/retry, no market, no cached locations and no matching rows each have distinct messages. Keep the current market, date and city drill-through routes.

Use a compact, horizontally scrollable table on phones, labeled controls with at least 16px editable text, 44px touch targets, visible keyboard focus and semantic tables/disclosures. No page-wide overflow at 320/390px. The map uses the same filtered rows; its bubble-size description must name the count actually used.
