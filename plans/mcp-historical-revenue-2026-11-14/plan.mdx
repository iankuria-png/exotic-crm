## Evidence and decisions

The connected tool schema lacks from/to on trend and market tools. A live summary with from=2026-08-01 and to=2026-11-14 returned window.from=2026-10-16 and window.to=2026-11-14 while meta.filters echoed the requested dates and result_state=complete. The legacy CeoDashboardDataService::context only uses explicit dates when horizon=custom; its default branch substitutes 30d. Source release 33a77116 already adds exact-date dispatch and an aggregate payment view but deployment remains unverified. Its parser still rejects intervals over 366 days; the catalogue's coverage.from comes from Client.created_at.

Reuse the existing exact reporting path and aggregate SQL view. Preserve the default dashboard calculation for recognised preset windows. Validate unsupported/missing custom windows before dispatch, never silently substitute 30d. Permit historical intervals over a year while retaining the 50,000 candidate and 9,000 bucket limits as explicit errors. Keep the existing coverage.from/to fields for compatibility, label them client-record history, and add separately scoped retained payment-candidate dates with a completeness caveat. Do not claim retention proves provider settlement or that missing history means zero revenue.
