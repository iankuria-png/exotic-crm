The existing single-form profile/package correction remains the main flow. A saved correction takes precedence over starting a new correction and uses its original action and idempotency key. Automatic receipt polling refreshes a mounted form's saved server result without resetting user choices. Pending source/target steps use customer-service labels, not compensation codes. Completion remains visible after the form closes. A successful undo leaves funds unassigned and does not imply that payment records have been reconciled.

Legacy recovery is tightly bounded: only source-compensation effects whose restore snapshot equals the original snapshot after applying the old expiry normalization qualify. Verify immutable v2 source identity and preimage, unchanged current fingerprint, correction ownership and absence of a saved compensation result. Repair only the exact invalid restore payload, retain the same operation ID, audit the repair and retry through existing guarded fulfillment. A saved result, unrelated metadata difference, changed coverage or unsupported source remains on the existing read/review path; no blind retries of uncertain activations.

Related payment codes are advisory evidence, selected only from the receipt account's bound markets and a numeric `/n` suffix of the exact reference. Existing exact-reference matches are also checked for other completed records. Ignore cancelled/test/sandbox records; return bounded results with incomplete coverage explicit. Preview, new execute and resume/applyTarget immediately before any new target dispatch block assignment when related successful records exist or candidate coverage is truncated. A reserved request key never bypasses this guard; already committed targets retain readback/finalization. Undo can still finish. Completion copy says to review the other payment record before assigning when this hold remains. No code normalization or money mutation is introduced. Race-free general reconciliation of separately entered manual payments is outside this release.
