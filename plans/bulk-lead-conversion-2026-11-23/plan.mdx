## Verification

Run focused HTTP tests on in-memory SQLite, PHP lint/Pint on task files and the existing browser fixture tooling with API interception. Browser checks use actual Leads and bulk dialog components. Production inspection is source-only through registered FleetOps read. Actual WordPress creation on production remains a post-shipping acceptance step. Shipment preflight must verify exotic_crm_provisions in each intended market plus current credentials and the combined source/assets overlay. Code rollback restores prior files/build and preserves created client/profile/audit records; no automatic deletion. Expired/changed reviews require a new preview; already-converted leads return their existing client. Test busy locks, selected duplicate contacts, token expiry/tampering, permission changes and WP success then CRM failure then edited/new-preview retry. MySQL row-lock concurrency is a shipment acceptance check; SQLite cannot establish it.
