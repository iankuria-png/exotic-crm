## Outcome and authorization

The CRM currently waits 45 seconds for OpenRouter DeepSeek V3.2 to time out, then Qwen often spends its entire 183-token allowance on reasoning. The production audit recorded 32 timeouts and 30 empty Qwen responses across 3–4 November. Short drafts should use their tokens for the bio and finish within a bounded sequence of attempts.

Ian's 4 November instruction, “Go ahead with your reccomendations”, authorizes the evaluated reasoning controls, timing, bounded fallback and small candidate comparison. This plan makes that approved direction concrete; it introduces no new product choice. Code, tests, build and review artifacts proceed under that authorization. Commit/push/production rollout and settings promotion are separate delivery actions requiring their applicable authorization after a concrete release is ready.

## Execution contract

Create a per-request BioGenerationRun only when the CRM controller passes a server-owned interactive flag. Existing WordPress service callers, bulk jobs, PBN jobs, translation and AiGateway keep their existing budgets and reasoning behavior. Extend LlmResponse with optional model/provider/finish/reasoning metadata, preserving its existing constructor defaults. Interactive visible output uses max(384,min(2048,ceil(max_words*2.5)+96)) tokens; the 75-word benchmark therefore uses the same 384-token allowance. Export synthetic prompts through the actual BioGenerationService prompt builder with empty synthetic feedback so route comparison uses the real house/language/length constraints; retain each payload hash.

The run uses monotonic time:30-second cooperative outbound-I/O deadline,12-second maximum per AI attempt,3-second connection timeout,2 actual AI attempts total including an optional rewrite, and 2 seconds reserved for finalization. Snapshot and cold catalogue reads receive a bounded single-read clone of WpSyncService: timeout=min(3-seconds, shared remaining minus finalization reserve), with no read started after exhaustion and no minimum-one-second clamp. A rewrite is allowed only with an unused attempt and at least 8 seconds plus the finalization reserve remaining. Exhaustion keeps the existing quality flags/draft or existing template fallback; response explicitly reports why an optional rewrite was skipped.

This deadline bounds network operations cooperatively; it is not a process-kill guarantee for arbitrary PHP/DB/CPU work. No Axios timeout assumption: the modal uses raw fetch.

## Provider controls and privacy

OpenRouter receives `reasoning.enabled=false` for the benchmarked optional-reasoning families and interactive bios; Mistral requests omit unsupported reasoning parameters. Route selection continues using configured models, preserving data_collection=deny. Direct DeepSeek uses thinking.type=disabled. Other configured providers honor shared timeouts/attempt metadata when invoked by interactive bios, without globally changing their parameters. Interactive exact-model selections do not silently try a different model. Legacy unscoped callers retain their existing fallback behavior.

Reject empty, refused or explicitly truncated interactive responses instead of presenting them as complete bios. A short cache circuit keyed by credential fingerprint/provider/model/mode opens after two transport/HTTP429/HTTP5xx infrastructure failures for 60 seconds and resets on success; cache failures fail open. Content refusals, truncation, empty outputs, local deadline exhaustion and programming errors do not poison a shared provider circuit. The circuit key also distinguishes routing and reasoning settings. Circuit skips do not consume HTTP attempts. No raw response/error bodies, prompts, contacts or bios enter the performance log. Emit exactly one safe terminal timing summary from a finally path, including snapshot/scoring exceptions; missing/unwritable logging fails open. Sanitize scoped errors before they reach existing adapter/waterfall/controller logs, with tests injecting credentials/prompts/bios into exception messages. Successful and failed timing summaries go to a dedicated daily INFO channel with 14-day retention and no incident-ingestion tap; general production LOG_LEVEL stays unchanged.

WordPress ownership and HMAC/Basic headers remain in WpSyncService. Add only an opt-in read budget on a cloned service instance, reusing its health gate, header builder and decoder; unscoped retry paths stay unchanged. The live WpSyncService hash differs from local, so production delivery must merge only the owned additive hunks against fresh live source instead of overwriting unrelated live differences.

The link catalogue caches a fully successful fetch for 60 minutes and retains a last-good copy for 24 hours. A failed budgeted fetch returns last-good entries (or static service entries when none exist), opens only a 15-second failure backoff and never stores that partial result under the normal one-hour key. Test cold failure followed by recovery and preservation of valid location/attribute links.

## Bounded candidate comparison

Register an Ops read diagnostic with inert default and an explicit --sample option. Preview resolves exact CRM identity, credential presence, 16 fixed synthetic requests and payload hashes; it makes no provider calls. Sampling is covered by the approved candidate comparison; its only external side effect is billed synthetic inference, with at most 16 candidate requests (or exactly 8 for --phase=baseline), 384 output tokens each,12-second per-call/240-second process admission, and no retries or application/WordPress writes. Validate the exact expected fixture hash on execution; leave the dirty-repository apply guard unchanged. Keys decrypt in server memory and never leave the server. Use synthetic adult profile facts without real names, phones or customer content. Keep generated synthetic responses private for quality review.

Compare four routes in counterbalanced order across English, French, Portuguese and Swahili: direct deepseek-flash without thinking, OpenRouter deepseek/deepseek-v4.1-flash-1017 default routing, the same snapshot with latency sorting, and existing mistralai/mistral-medium-3.1. Preserve deny-data-collection on OpenRouter. Store status, finish reason, total time, reported reasoning tokens, visible text length, token costs when returned and the synthetic output. After output/transport loss inspect the retained ledger before replaying any billed batch. Pass the synthetic responses through the actual sanitizer/length/uniqueness pipeline before promoting a production default; otherwise label results API-only. Review language, factuality,60–75 words,900-character limit and existing uniqueness/sanitization/SEO behavior. Four samples per route support a small comparison, not fleet p95 or a guaranteed SLA.

The initial16-request comparison completed with16HTTP200/stop/zero-reasoning results, but several non-English outputs were in English and Mistral was consistently shorter than requested. No global model promotion is justified. Extend the already approved small comparison by exactly8 synthetic requests: the saved DeepSeekV3.2 model with reasoning disabled, default and latency sorting, across the same four frozen language fixtures. Total inference calls for this task are capped at24 (16completed plus8targeted), with the same12second/384token limits and no customer/settings writes. The second phase is separately pinned as --phase=baseline; no automatic replay or open-ended tuning batch. This validates the combined reasoning-off/384-token payload on the existing primary instead of assuming a new snapshot is better.

Prepare an exact settings diff for the observed winner and one tested fallback; preserve encrypted keys and all unrelated settings. Migration of the saved legacy direct DeepSeek alias and candidate/default promotion belong in that artifact, not a hidden code override. If no route meets quality/reliability, retain the current default and report the blocker rather than promote on speed alone.
