# Task: profile-media metadata backfill

- ID / project: Exotic CRM + local `exotic-crm-sync` WordPress plugin
- Updated / status: 2026-09-22 / CRM pushed as `d3099d4c`; awaiting cPanel pull and migration; not deployed
- Goal and acceptance criteria: From the Clients workspace, an admin or sub-admin can preview and queue a repair of existing WordPress attachment titles and Media Library descriptions for selected profiles or an entire market. The run must be visible while it progresses, avoid overlapping work for a market, and keep normal CRM queues responsive.
- Scope / decisions: The run changes attachment `post_title` and `post_content` only. It does not edit profile fields, image/video files, alt text, or main-image selection. It is restricted to one market and one active run per market. Selected scopes allow up to 150 client IDs; unlinked clients are previewed as skipped.
- Queue design: `ProfileMediaMetadataBackfillRun` persists scope, cursor, counts and recent failures. `RunProfileMediaMetadataBackfillJob` uses the existing `database_long` / `heavy` lane, platform cache lock and five-profile slices with a five-second handoff. A profile without attachments increments skipped; individual WordPress failures are logged and retained in the run notes without halting other profiles.
- WordPress interface: `POST /wp-json/exotic-crm-sync/v1/clients/{post_id}/media/metadata`, protected by the same sync/admin permission callback as the existing media routes, calls `synchronize_profile_media_metadata()` and returns `attachments_updated`.
- CRM interface: admin/sub-admin routes are `POST /api/crm/clients/media-metadata-backfill/preview`, `POST /api/crm/clients/media-metadata-backfill/runs`, and `GET /api/crm/clients/media-metadata-backfill/runs/{run}`. The Clients page supplies market/selected scopes, preview, confirmation, live polling and failure notes.
