# CRM UI rules

Preserved from the previous CLAUDE instructions, 2026-09-20.
- Match the existing design language and provide a high-quality result without a reminder.
- Lists/tables support filters and export; row actions should not require navigating away.
- Async work exposes progress/health. Design empty, loading and error states.
- Keep raw UUIDs/URLs revealable/copyable rather than dominant in the UI.
- Convert currencies consistently or hide incomparable totals; never silently mix them.
- Dashboard widgets support their appropriate market switchers.
- Use one primary design skill (normally impeccable for substantial frontend work), then
  specialist skills only when relevant. Preserve business observability and controls.
